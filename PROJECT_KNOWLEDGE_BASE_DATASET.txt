# BAGIAN 1: TINJAUAN EKSEKUTIF (EXECUTIVE SUMMARY)

## 1.1 Visi & Misi
**Geges Smart Barber** bukan sekadar aplikasi booking, melainkan ekosistem digital revolusioner untuk industri pangkas rambut. Misi utamanya adalah:
1.  **Bagi Customer:** Menghapus waktu tunggu yang sia-sia dengan sistem booking presisi.
2.  **Bagi Barber/Owner:** Mendigitalkan manajemen antrean, keuangan, dan performa karyawan secara real-time.
3.  **Bagi Industri:** Menciptakan standar baru layanan barbershop yang modern, transparan, dan berbasis data.

## 1.2 Cakupan Ekosistem (Ecosystem Scope)
Proyek ini terdiri dari tiga komponen utama yang saling terintegrasi:
1.  **Mobile App (Flutter):**
    *   *Customer App:* Booking, Pembayaran, AI StyleScan, Chatbot.
    *   *Tenant App:* Pendaftaran franchise, manajemen dokumen legal.
2.  **Web Admin Panel (React/Flutter Web - Konteks Eksternal):**
    *   *Super Admin Dashboard:* Verifikasi global, manajemen user, refund processing.
3.  **Backend Infrastructure (Google Firebase):**
    *   *Firestore:* Database NoSQL real-time.
    *   *Firebase Auth:* Manajemen identitas dan sesi.
    *   *FCM:* Notifikasi push lintas platform.

# BAGIAN 2: ARSITEKTUR TEKNIS (TECHNICAL ARCHITECTURE)

## 2.1 Desain Sistem (System Design)
Aplikasi dibangun menggunakan pola arsitektur **MVVM (Model-View-ViewModel)** yang disesuaikan untuk Flutter (Service-Repository Pattern).
*   **Screens (UI):** Hanya menangani rendering dan interaksi user.
*   **Services (Logic):** Menangani komunikasi ke Firestore, logika bisnis, dan error handling.
*   **Models (Data):** Representasi objek data (Dart Class) dengan serialisasi JSON.

## 2.2 Batasan Teknis & Solusi (Constraints & Solutions)
Proyek ini dioptimalkan untuk **Firebase Spark Plan** (Gratis), yang memiliki batasan ketat:
*   **Tanpa Cloud Functions:** Semua logika (seperti pengiriman email, rekap harian) dijalankan di sisi client (Admin App) atau dipicu oleh action user.
*   **Tanpa Firebase Storage:**
    *   *Masalah:* Tidak bisa upload file blob.
    *   *Solusi:* Gambar dikompresi (max 800px), diubah ke format WEBP/JPEG, lalu di-encode menjadi string **Base64**. String ini disimpan langsung di dokumen Firestore atau sub-collection `documents` untuk file besar.
*   **Tanpa Server Side Search (Algolia/Elastic):**
    *   *Solusi:* Implementasi pencarian *client-side* untuk dataset kecil, atau penggunaan query Firestore dasar (`where`, `orderBy`) yang dikombinasikan dengan filter lokal.

## 2.3 Strategi Offline (Offline Capabilities)
Meskipun aplikasi sangat bergantung pada koneksi internet, beberapa fitur didukung offline:
*   **Persistence:** Firestore `persistenceEnabled: true`. Data yang pernah dimuat akan disimpan di cache lokal. User bisa melihat riwayat booking tanpa internet.
*   **Optimistic UI:** Saat user melakukan aksi (misal: "Mark as Read"), UI berubah duluan sebelum server merespon, memberikan kesan aplikasi yang sangat cepat.

# BAGIAN 3: SKEMA DATABASE LENGKAP (DATABASE SCHEMA DEEP DIVE)

## 3.1 Collection: `users`
*Root collection* untuk semua pengguna.
*   `uid` (PK, string): Firebase Auth UID.
*   `email` (string): Unique index.
*   `role` (string): `customer`, `admin_owner`, `super_admin`.
*   `name` (string): Display name.
*   `phone_number` (string): Format E.164 (+62...).
*   `photo_base_64` (string): Avatar user.
*   `fcm_token` (string): Token untuk push notification.
*   `created_at` (timestamp).
*   `last_login` (timestamp).
*   `favorite_barbershops` (array of strings): List ID barbershop favorit.

## 3.2 Collection: `barbershops`
Data master cabang.
*   `id` (PK, string): Auto-generated.
*   `owner_uid` (string): Reference ke `users.uid`.
*   `name` (string): Nama toko.
*   `address` (string): Alamat teks.
*   `geo_point` (GeoPoint): Lat/Long untuk fitur "Nearby".
*   `imageUrl` (string): Base64 cover photo.
*   `facilities` (array): ["AC", "Wifi", "Coffee"].
*   `open_hour` (int): 0-23.
*   `close_hour` (int): 0-23.
*   `isOpen` (bool): Master switch buka/tutup.
*   `isActive` (bool): Soft delete flag.
*   `rating` (double): Aggregated rating.
*   `review_count` (int).
*   `services` (array of strings): ID layanan yang ditawarkan.
*   `gallery_urls` (array of strings): Base64 foto galeri.

## 3.3 Collection: `services`
Katalog layanan global (Master Data).
*   `id` (PK, string).
*   `name` (string): "Gentlemen Cut", "Premium Shave".
*   `category` (string): "Hair", "Face", "Treatment".
*   `price` (int): Harga dasar.
*   `defaultDuration` (int): Estimasi waktu pengerjaan (menit).
*   `isActive` (bool).

## 3.4 Collection: `barbermen`
Data tukang cukur (Staff).
*   `id` (PK, string).
*   `barbershop_id` (string): FK ke `barbershops`.
*   `name` (string).
*   `imageUrl` (string): Base64 foto wajah.
*   `isActive` (bool): Status kepegawaian.
*   `onLeave` (bool): Status cuti hari ini.
*   `offDays` (array): ["monday", "thursday"].
*   `specificOffDays` (array): ["2025-12-25", "2026-01-01"].
*   `avgDuration` (double): Kecepatan cukur rata-rata (untuk penyesuaian jadwal).
*   `rating` (double).
*   `monthlyHaircutCount` (int): Counter untuk *Fairness Algorithm*. Reset tiap awal bulan.

## 3.5 Collection: `queues` (The Core Transaction)
Transaksi pemesanan. Dokumen ini yang paling sering di-update.
*   `id` (PK, string).
*   `order_id` (string): Readable ID (e.g., ORD-12345).
*   `customer_id` (string): FK `users`.
*   `barbershop_id` (string): FK `barbershops`.
*   `barberman_id` (string): FK `barbermen`.
*   `service_ids` (array): FK `services`.
*   `status` (enum string):
    *   `waiting` -> `awaiting_payment` -> `pending_verification` -> `booked` -> `ongoing` -> `served`.
    *   `cancelled` -> `refund_completed` / `refund_rejected`.
*   `booking_time` (timestamp): Slot jadwal.
*   `created_at` (timestamp).
*   `payment_deadline` (timestamp).
*   `total_price` (int).
*   `barber_selection_fee` (int).
*   `payment_proof_base64` (string).
*   `refund_proof_base64` (string).
*   `cancel_reason` (string).
*   `admin_notes` (string).
*   `is_auto_assigned` (bool).

## 3.6 Collection: `tenants` (Registration Logic)
*   `id` (PK, string).
*   `owner_uid` (string).
*   `business_name` (string).
*   `status` (enum): `draft`, `awaiting_payment`, `active`, `rejected`.
*   `invoice` (map): Detail tagihan pendaftaran.
*   `payment` (map): Bukti bayar pendaftaran.
*   `documents` (sub-collection):
    *   `type`: "SIUP" / "NPWP".
    *   `content_base64`: Data file.

# BAGIAN 4: LOGIKA BISNIS & ALGORITMA (CORE LOGIC)

## 4.1 Fairness Algorithm (Algoritma Pemerataan Job)
Masalah: Tukang cukur populer terlalu sibuk, tukang cukur baru sepi.
Solusi: Jika user memilih "Dipilihkan Sistem", algoritma ini berjalan:
1.  **Filter Ketersediaan:** Ambil semua barber yang `isActive=true`, `onLeave=false`, dan tidak sedang libur (`offDays`).
2.  **Filter Jadwal:** Cek `queues` untuk hari itu. Eliminasi barber yang sudah penuh di jam yang diminta user.
3.  **Sorting:** Urutkan barber yang tersisa berdasarkan `monthlyHaircutCount` dari yang **terkecil** ke terbesar.
4.  **Selection:** Pilih barber pertama (paling sedikit job).
5.  **Update:** Setelah booking sukses, increment `monthlyHaircutCount` barber tersebut.

## 4.2 Dynamic Pricing & Fee
Harga total dihitung real-time:
*   `Base Price` = Sum(Service Prices).
*   `Selection Fee` = Jika user pilih barber spesifik (bukan sistem), tambah `barbershop.barber_selection_fee` (e.g., +10k).
*   `Total` = Base Price + Selection Fee.

## 4.3 Slot Management (Anti-Clash System)
Mencegah *double booking* pada jam yang sama.
*   Sistem menggunakan `Transaction` Firestore saat membuat booking.
*   **Logic:**
    1.  Baca semua dokumen `queues` pada `barbershop_id` & `barberman_id` terpilih.
    2.  Filter booking dengan status aktif (`booked`, `ongoing`, `awaiting_payment`).
    3.  Cek irisan waktu (Time Intersection):
        *   `NewStart < ExistingEnd` AND `NewEnd > ExistingStart`
    4.  Jika ada irisan -> **Throw Error ("Slot Penuh")**.
    5.  Jika bersih -> Commit booking baru.

## 4.4 Tenant State Machine
Mengatur lifecycle pendaftaran mitra agar tidak ada data sampah.
*   `Draft`: User baru isi form.
*   `Awaiting Payment`: User setuju S&K, upload dokumen. Invoice terbit.
*   `Waiting Proof`: User di halaman bayar. Timer mundur.
*   `Payment Submitted`: User upload bukti. Data dikunci (Read-only).
*   `Active`: Admin approve. Role user -> `admin_owner`. Toko dibuat.
*   `Rejected`: Admin tolak. User bisa revisi atau minta refund.

# BAGIAN 5: FLOW APLIKASI MENDETAIL (USER JOURNEY)

## 5.1 Customer Journey: Booking
1.  **Discovery:** User buka app -> Lokasi dideteksi -> List toko terdekat muncul.
2.  **Selection:** User klik toko -> Lihat portofolio (Album) -> Baca review.
3.  **Config:** User pilih "Cut + Wash" -> Pilih "Barber Andi" -> Pilih "Besok 10:00".
4.  **Payment:**
    *   User melihat ringkasan.
    *   Transfer ke BCA.
    *   Upload screenshot.
5.  **Waiting:** Status "Menunggu Verifikasi".
6.  **Confirmed:** Notifikasi "Booking Terkonfirmasi". QR Code tiket muncul.
7.  **Service:** User datang -> Tunjukkan QR/ID -> Dicukur.
8.  **Post-Service:** User beri rating & tip (opsional).

## 5.2 Admin Journey: Verifikasi & Operasional
1.  **Morning Routine:** Owner buka app Admin -> Setel "Toko Buka". Cek barber yang hadir.
2.  **Incoming Order:** Notifikasi masuk "Booking Baru". Admin cek di dashboard.
3.  **Payment Check:** Admin cek mutasi bank. Jika cocok, klik "Terima".
4.  **Queue Management:**
    *   Pelanggan datang -> Admin klik "Check In" / "Mulai".
    *   Layanan selesai -> Admin klik "Selesai".
5.  **Closing:** Malam hari, admin cek "Laporan Harian" -> Tutup Toko.

## 5.3 Super Admin: Refund Processing
1.  User request refund di app -> Status `cancellation_requested`.
2.  Super Admin dapat notifikasi di Web Panel.
3.  Cek alasan & bukti bayar user.
4.  Transfer balik dana (manual via bank).
5.  Upload bukti transfer refund ke panel.
6.  Klik "Mark Refunded".
7.  App user update status -> Tampilkan bukti refund.

# BAGIAN 6: KEAMANAN & PRIVASI (SECURITY PROTOCOLS)

## 6.1 Data Privacy (GDPR Compliance Concept)
*   **Foto Profil:** Disimpan Base64 kualitas rendah (thumbnail).
*   **Dokumen Legal:** Hanya bisa diakses oleh uploader (Owner) dan Super Admin. Tidak publik.
*   **Right to be Forgotten:** Fitur "Hapus Akun" di profile akan menghapus data user dari `users` collection, namun menyisakan data transaksi (`queues`) secara anonim untuk integritas laporan keuangan.

## 6.2 Fraud Prevention
*   **Rate Limiting:** User dibatasi hanya boleh memiliki 1 booking status `waiting` per toko untuk mencegah spam slot.
*   **Payment Lock:** Setelah bukti bayar diupload, user tidak bisa mengganti foto bukti kecuali diminta revisi oleh admin.
*   **Device Binding:** Token FCM diikat ke device ID untuk memastikan notifikasi sampai ke HP yang benar.

# BAGIAN 8: PANDUAN ERROR & SOLUSI (TROUBLESHOOTING DICTIONARY)

Kumpulan kode error dan solusi teknis untuk tim support.

| Kode Error / Gejala | Penyebab Teknis | Solusi User / Support |
| :--- | :--- | :--- |
| **ERR_SLOT_FULL** | Transaksi bentrok saat commit database. | Minta user pilih jam lain yang kosong. |
| **IMG_TOO_LARGE** | File > 1MB (Limit Base64 Firestore). | Minta user crop/kompres foto, atau kirim via WA. |
| **AUTH_WEAK_PASS** | Password < 6 karakter. | User harus buat password lebih panjang. |
| **GPS_TIMEOUT** | Geolocator gagal dapat lock dalam 5 detik. | Pastikan GPS nyala, coba di luar ruangan. |
| **PAYMENT_REJECTED** | Admin menolak bukti di panel. | Cek notifikasi alasan penolakan, upload ulang. |
| **WHITE_SCREEN** | Memory leak / Image decoding crash. | Restart aplikasi (Kill & Open). |

# BAGIAN 9: KAMUS ISTILAH LENGKAP (GLOSSARY)

*   **RAG (Retrieval-Augmented Generation):** Teknik AI dimana chatbot mencari jawaban dari dokumen ini sebelum menjawab user.
*   **Base64:** Cara mengubah gambar menjadi teks panjang agar bisa disimpan di database tanpa storage server.
*   **Firestore:** Database tempat kita menyimpan semua data.
*   **Collection:** Seperti "Folder" atau "Tabel" di database (contoh: folder `users`).
*   **Document:** Seperti "File" atau "Baris" di database (contoh: data `budi`).
*   **Field:** Data spesifik dalam dokumen (contoh: `nama: budi`).
*   **FCM (Firebase Cloud Messaging):** Sistem kurir notifikasi.
*   **State Management:** Cara aplikasi mengingat data (misal: "User sedang login").
*   **Dependency Injection:** Cara coding agar bagian-bagian aplikasi bisa diganti-ganti (misal untuk testing).
