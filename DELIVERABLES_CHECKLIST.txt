================================================================================
  WHAT'S FIXED
================================================================================

BEFORE (Problems):
❌ Customers could upload payment proof multiple times → duplicate entries
❌ Same booking appeared in multiple tabs simultaneously
❌ Status inconsistencies between My Bookings and Admin panels
❌ No way to prevent race conditions on concurrent uploads
❌ Manual admin intervention needed to clean up duplicates
❌ No real-time UI updates on payment status changes

AFTER (Solutions):
✅ Payment proof can only be uploaded once (proofLocked = true after first submit)
✅ Transaction safety: first upload wins, subsequent attempts fail gracefully
✅ Each booking appears in exactly ONE tab (mutually exclusive queries)
✅ Real-time snapshot listeners keep UI in sync with Firestore
✅ Firestore transactions prevent all race conditions
✅ Service layer includes duplicate identification & cleanup tools
✅ Admin can verify/reject with option to allow re-upload

================================================================================
  QA TEST CASES (8 Mandatory)
================================================================================

1. ✅ Single Upload Success
   - Customer uploads once
   - Expect: transaction succeeds, button locks, badge shows "Menunggu Verifikasi"

2. ✅ Block Concurrent Double-Upload
   - 2 clients upload simultaneously
   - Expect: only 1 succeeds, other gets error "bukti sudah dikirim"

3. ✅ No Duplicate Doc Creation
   - Same booking ID uploaded
   - Expect: 1 document in Firestore (not 2 or 3)

4. ✅ Admin Filter Only Pending
   - 3 bookings: uploaded, rejected, paid_verified
   - Expect: admin screen shows only 1 (the pending one)

5. ✅ Customer Cannot Re-Pay
   - After upload, button disabled
   - Expect: button greyed out, not clickable

6. ✅ Rejected Path with Re-Upload
   - Admin rejects with "allow re-upload" checked
   - Expect: proofLocked=false, proofUrl=null, button enabled again

7. ✅ Query Exclusivity (No Overlap)
   - 5 bookings in different states
   - Expect: each appears in exactly ONE tab, never 2

8. ✅ UI Snapshot Consistency
   - Admin verifies payment in real-time
   - Expect: customer UI updates within 2-3 seconds
