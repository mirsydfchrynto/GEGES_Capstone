## BAB 1: PENDAHULUAN & LATAR BELAKANG (BIG PICTURE)

Halo Agent. Kita sedang dalam misi besar untuk menyempurnakan ekosistem digital bernama "Geges Smart Barber". Ini bukan sekadar aplikasi booking pangkas rambut biasa; ini adalah **Sistem Multi-Tenant (SaaS)**. Bayangkan ini seperti "GrabFood" atau "Gofood", tapi khusus untuk Barbershop.

### Status Project Saat Ini (Existing Condition)
Saat ini, kita sudah memiliki **Aplikasi Mobile (Flutter)** yang sudah aktif dan berfungsi. Berikut adalah alur yang sudah berjalan di sisi mobile:
1.  **Customer** (pengguna biasa) bisa login.
2.  Customer bisa masuk ke menu "Gabung Mitra" (Register Tenant).
3.  Mereka mengisi form pendaftaran (Nama Bisnis, Paket Langganan, dll).
4.  Mereka mengunggah **Bukti Pembayaran** dan Dokumen Pendukung. Karena keterbatasan infrastruktur, gambar ini diunggah bukan ke Cloud Storage, melainkan dikonversi menjadi string **Base64** dan disimpan langsung di dokumen Firestore.
5.  Setelah submit, status mereka di database menjadi `waiting_proof` atau `pending`.

### Masalah (The Problem)
Di sinilah kita berhenti. Saat ini, Customer yang sudah mendaftar dan bayar itu "terjebak". Tidak ada sistem yang memproses pendaftaran mereka. Kita belum memiliki "Pintu Belakang" atau Dashboard untuk Super Admin memverifikasi data tersebut. Kita butuh jembatan untuk mengubah status mereka dari "Pendaftar" menjadi "Pemilik Bisnis Resmi".

## BAB 3: KETERBATASAN TEKNIS & REALITA INFRASTRUKTUR (CRITICAL)

Dengarkan baik-baik bagian ini, karena ini adalah **Hukum Alam** di project ini. Jika kamu melanggarnya, sistem akan gagal total. Kita menggunakan **Firebase Spark Plan (Gratis)**, yang artinya:

### 1. DILARANG KERAS Menggunakan Cloud Functions
Kita tidak punya backend server-less. Biasanya, logika pembuatan akun user lain dilakukan di backend. Tapi di sini, **TIDAK BISA**.
*   **Solusi Kamu:** Kamu harus menerapkan pola **"Secondary Firebase App Instance"**.
*   **Penjelasan:** Di dalam kode React (Frontend), saat Admin klik Approve, kamu harus menginisialisasi *instance* Firebase kedua secara sementara, gunakan instance itu untuk membuat user baru (`createUserWithEmailAndPassword`), ambil UID-nya, lalu hapus instance tersebut. Ini mencegah Admin ter-logout dari akunnya sendiri.

### 2. DILARANG KERAS Menggunakan Firebase Storage
Kita tidak punya bucket penyimpanan gambar.
*   **Solusi Kamu:** Semua gambar (Logo Barbershop, Bukti Bayar, Foto Profil) harus dikelola sebagai **String Base64**.
*   **Perhatian:** Saat menampilkan gambar di website, gunakan tag `<img src="data:image/jpeg;base64,..." />`. Pastikan kamu menangani string yang panjang ini dengan efisien agar browser tidak crash (gunakan *lazy loading* atau optimasi render).

## BAB 6: ALUR KERJA LOGIKA "APPROVE" (THE CORE ENGINE)

Saya minta kamu membuat sebuah fungsi khusus (bisa di dalam Service atau Redux Thunk) bernama `approveTenantRegistration`. Fungsi ini harus menjalankan langkah-langkah atomik berikut secara berurutan:

1.  **Validasi Awal:** Pastikan data tenant lengkap.
2.  **Generate Password:** Buat password acak yang aman (misal 10 karakter alfanumerik).
3.  **Auth Creation (Secondary App):**
    *   Inisialisasi `secondaryApp`.
    *   Create User dengan email pendaftar dan password acak tadi.
    *   Dapatkan `newUid`.
    *   Hapus `secondaryApp`.
4.  **Database Batch Write (Firestore):**
    *   Buat Doc `barbershops/{newShopId}`.
    *   Buat Doc `users/{newUid}` dengan role `admin_owner` dan `barbershop_id` yang baru.
    *   Buat Doc `notifications` ke user lama berisi kredensial baru.
    *   Update Doc `tenants/{tenantId}` set status `active` dan payment `verified`.
5.  **Feedback:** Tampilkan notifikasi Sukses di layar Admin.
