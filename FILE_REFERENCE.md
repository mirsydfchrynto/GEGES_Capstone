## 🎯 Fitur-Fitur Utama

### 1. Notifikasi In-App (Firestore-driven)
**File Kunci:**
- `lib/services/notification_service.dart` — Listen Firestore, tampilkan local notification
- `lib/screens/admin/send_notification_screen.dart` — Admin buat notifikasi
- `lib/services/queue_service.dart` — Auto-create notifications ketika admin action

**Alur:**
1. Admin buat notifikasi via `SendNotificationScreen`
2. Disimpan di Firestore `notifications` collection
3. Client `NotificationService` listen & tampilkan local OS notification
4. Customer tap → navigate ke booking (via `app_navigator.dart`)

---

### 2. Notifikasi Push FCM (Optional)
**File Kunci:**
- `scripts/fcm_sender/send_push.js` — CLI script untuk push manual
- `scripts/fcm_sender/server.js` — Express server untuk push processing
- Firestore `push_requests` collection — Queue untuk pending pushes

**Alur:**
1. Admin centang "Kirim push melalui server" → create `push_requests` doc
2. Server helper process `push_requests` via FCM API
3. Customer device terima push notification
4. Mark `push_requests.processed = true`

---

### 3. Payment Verification Flow
**File Kunci:**
- `lib/screens/customer/booking_detail_screen.dart` — Upload payment proof
- `lib/screens/admin/payment_verification_screen.dart` — Admin verify proof
- `lib/services/queue_service.dart` — Handle status transitions

**Alur:**
1. Admin approve booking → status `awaiting_payment` (10 menit)
2. Customer see countdown, upload foto bukti bayar
3. Admin verify photo → confirm or reject
4. Status → `booked` (confirm) atau `cancelled` (reject)

**Per-Barbershop Payment Window:**
- The `payment_deadline` for `awaiting_payment` bookings is set from a per-shop field `payment_window_minutes` if present; otherwise a **10-minute** default is used. This value is stored on the `barbershops` document and read by `QueueService` when creating bookings.

## 🔧 Client App Files Explained

### `lib/services/notification_service.dart`
```dart
// Responsibilities:
- Initialize FCM (request permission, get token)
- Save token to Firestore (users/{uid}.fcm_token)
- Initialize flutter_local_notifications
- Listen to Firestore notifications collection (personal + broadcast)
- Show local OS notifications
- Handle notification tap (navigate to BookingDetailScreen)
- Handle FCM foreground messages (onMessage)
- Handle FCM tap when app opened (onMessageOpenedApp)
- Handle app launched from notification in terminated state (getInitialMessage)

// Key methods:
- init() — initialize all
- _startNotificationsListener(uid) — listen personal + broadcast docs
- _showLocalNotification() — show OS notification
- _handleNotificationTap() — navigate when tapped
- _saveTokenToFirestore() — save FCM token
```

### `lib/services/app_navigator.dart`
```dart
// Simple file:
final appNavigatorKey = GlobalKey<NavigatorState>();

// Used by:
- MaterialApp(navigatorKey: appNavigatorKey, ...)
- NotificationService._handleNotificationTap() to push routes
```

### `lib/screens/admin/send_notification_screen.dart`
```dart
// UI Fields:
- User ID search (debounced, autocomplete)
- Judul, Isi
- Queue ID (optional)
- Broadcast toggle

// Behavior:
- If broadcast: create notifications doc with broadcast=true
- If personal: require user_id, create notifications doc with user_id
- If "kirim push": also create push_requests doc
- Auto-complete search users by name (orderBy + startAt/endAt)
```

## 🖥️ Server Helper Files Explained

### `scripts/fcm_sender/send_push.js`
```bash
# CLI Usage:
node send_push.js --type=broadcast --title="..." --body="..."
node send_push.js --type=personal --uid=<UID> --title="..." --body="..."
node send_push.js --processPending

# Requirements:
- GOOGLE_APPLICATION_CREDENTIALS env var (Firebase service account path)
- Firebase Admin SDK initialized

# Key functions:
- broadcast() — send to all users with fcm_token
- sendToUser() — send to specific user
- processPendingRequests() — process push_requests from Firestore
```

### `scripts/fcm_sender/server.js`
```bash
# HTTP Endpoints:
GET /health
POST /process-push (requires x-api-key header)

# Requirements:
- GOOGLE_APPLICATION_CREDENTIALS env var
- PROCESS_API_KEY env var
- PORT env var (optional, default 4000)

# Behavior:
- Process up to 50 pending push_requests per call
- Mark processed_at + result status
- Return JSON response
```

## 📊 Data Models & Collections

### Firestore Collection: `users/{uid}`
```
{
  uid: String,
  name: String,
  email: String,
  role: "customer" | "admin_owner",
  phone_number: String,
  fcm_token: String,              // ⭐ NEW: Device token for push
  fcm_token_updated_at: Timestamp,
  created_at: Timestamp
}
```

### Firestore Collection: `notifications/{doc_id}`
```
{
  title: String,
  body: String,
  user_id: String,                // UID customer (empty if broadcast)
  broadcast: Boolean,              // true = all users
  queue_id: String,               // (optional) booking ID
  created_at: Timestamp,
  delivered: Boolean,              // false → true after shown
  delivered_at: Timestamp,
  read: Boolean (optional)
}
```

### Firestore Collection: `push_requests/{doc_id}`
```
{
  title: String,
  body: String,
  user_id: String,                // (empty if broadcast)
  broadcast: Boolean,
  queue_id: String,               // (optional)
  created_at: Timestamp,
  processed: Boolean,              // false → true after sent
  processed_at: Timestamp,
  result: String                  // "ok" or "error: ..."
}
```

### Firestore Collection: `queues/{queue_id}`
```
{
  customerId: String,
  status: "waiting" | "awaiting_payment" | "booked" | "ongoing" | "served" | "cancelled",
  payment_due_at: Timestamp,      // (set by adminConfirmRequest)
  payment_proof_base64: String,   // (base64 image, uploaded by customer)
  created_at: Timestamp
  // ... other fields
}
```

## 🔐 Security Considerations

### Service Account Protection
- ❌ Never commit `.json` file to git
- ✅ Store in `~/secure/` or environment variables
- ✅ Restrict file permissions: `chmod 600`
- ✅ Rotate periodically

### API Key Protection
- ❌ Never hardcode in app
- ✅ Generate random strong key (min 32 chars)
- ✅ Store in `.env` (not committed)
- ✅ Only shared to trusted services

### Firestore Rules
- ❌ Don't use `allow read, write: if true` in production
- ✅ Use auth-based rules (see SETUP_OPERATIONS_CHECKLIST.md)
- ✅ Restrict `notifications` write to server only
- ✅ Allow `push_requests` write from app (with limits)

## 🚀 Deployment Architecture

### Development
```
Flutter App (emulator/device)
    ↓ (Firestore)
Firestore (dev)
    ↓ (read notifications)
NotificationService (in-app)
    ↓
Customer sees notification
```

### Production (In-App Only)
```
Flutter App (Play Store/App Store)
    ↓ (Firestore)
Firestore (production)
    ↓ (read notifications)
NotificationService (in-app)
    ↓
Customer sees notification
```

### Production (With Push)
```
Flask/Node Server (internal)
    ↓ (process push_requests)
Firestore (production)
    ↓ (read users.fcm_token)
Firebase Cloud Messaging (FCM)
    ↓
Customer device (push notification)
```

## 🆘 Common Questions

**Q: Dimana notifikasi disimpan?**
A: Firestore collection `notifications/{doc_id}`. Lihat schema di bagian Data Models.

**Q: Gimana customer tahu booking sudah disetujui?**
A: Automatic! Ketika admin tap "Approve", `queue_service.dart` langsung buat notification doc.

**Q: Apa bedanya `notifications` dan `push_requests`?**
A: `notifications` = in-app (ditampilkan oleh NotificationService). `push_requests` = server processing untuk FCM push.

**Q: Harus punya server untuk push?**
A: Tidak wajib. In-app notifications berfungsi tanpa server. Push adalah optional enhancement.

**Q: Bagaimana kalau customer tidak punya internet?**
A: In-app notification tidak bisa sampai (Firestore membutuhkan internet). Tapi payment proof upload bisa di-queue untuk later.

**Q: Payment proof simpan di mana?**
A: Sekarang di Firestore sebagai base64. Bisa migrasi ke Firebase Storage kemudian untuk optimization.
